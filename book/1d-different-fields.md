# Documentation in different fields  

Different scientific fields have different documentation practices.  This table shows a few examples of the types of documentation typically used in different types of projects [make this a table in the Jupyter book with column headers type of project/documentation practices]:  

Experimental research: lab notebooks, experimental protocols, instrument settings and conditions 

Data-intensive research: README files, data dictionaries, metadata standards 

Software/computational research: code comments, software READMEs, version control, computational notebooks 

Design/Hardware: CAD/design files, specifications, component lists, assembly instructions, design decisions, and version history. 

 

You do not need to invent documentation practices from scratch! Instead, you should investigate whether your discipline or community has established standards, templates, or conventions that you can follow. Here are some suggestions to learn more about documentation in your field:   

- Discuss norms for documentation with your project supervisor. 

- Visit a repository specific to your discipline to get a sense of how researchers provide documentation for research objects within your field. Re3data helps you to find discipline-specific repositories using keywords. Try doing a search by typing your project topic into Re3data's search window.  

- Ask a Data Steward. Each faculty at TU Delft has at least one data steward on staff who supports researchers with data management. Visit this Contact the Data Stewards page to find the data steward for your faculty.
