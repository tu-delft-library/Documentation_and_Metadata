# 1d. Documentation in different fields  

## Documentation by discipline 

Different scientific fields have different documentation practices.  This table shows a few examples of the types of documentation typically used in different types of projects:  

| Type of Project | Documentation Practices |
|---------|--------|
| **Experimental research** | lab notebooks, experimental protocols, instrument settings and conditions |
| **Data-intensive research** | README files, data dictionaries, metadata standards |
| **Software/computational research** | code comments, software READMEs, version control, computational notebooks |
| **Design/hardware** | CAD/design files, specifications, component lists, assembly instructions, design decisions, and version history | 


## Explore standards for your field 
You do not need to invent documentation practices from scratch! Instead, you should investigate whether your discipline or community has established standards, templates, or conventions that you can follow. Here are some suggestions to learn more about documentation in your field:   

- Discuss norms for documentation with your project supervisor. 

- Visit a repository specific to your discipline to get a sense of how researchers provide documentation for research objects within your field. <a href="https://www.re3data.org/" target="_blank"> Re3data </a>  helps you to find discipline-specific repositories using keywords. Try doing a search by typing your project topic into Re3data's search window.  

- Ask a Data Steward. Each faculty at TU Delft has at least one data steward on staff who supports researchers with data management. Visit the TU Delft Library's <a href="https://www.tudelft.nl/en/library/data-management/get-support-on-data-management/contact-the-data-stewards" target="_blank"> Contact the Data Stewards page </a> to find the data steward for your faculty.
